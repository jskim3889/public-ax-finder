# 공공 AX 사례 찾기

공공기관의 AI 도입 담당자가 문장으로 물으면, 다른 기관이 실제로 발주한 AI 관련 용역 사업 중 의미가 가까운 것을 찾아 주는 웹앱이다. KAIST ITM.690 실습 2-(ii) 과제.

- 데이터: 조달청 나라장터 발주계획현황서비스(공공데이터포털 15129462) 용역 중 AI 관련 사업 5,593건, 2024-01 ~ 2026-09 발주 예정분
- 실제 공고: 나라장터 입찰공고정보서비스(15129394)의 용역 공고를 발주계획의 입찰공고번호로 연결(4,623건). 공고일·개찰일·추정가격·계약방법·핵심 첨부 링크를 카드에 붙인다
- 방식: 사업명을 임베딩(qwen/qwen3-embedding-8b, 앞 1,024차원)해 두고, 질의 문장도 같은 방식으로 임베딩해 코사인 유사도 순으로 보여 준다
- 브라우저에는 키가 없다. 질의 문장만 서버로 가고, 서버가 OpenRouter 임베딩 API를 부른다

## 로컬에서 실행

필요한 것: Python 3 (3.14에서 확인), OpenRouter API 키

```bash
python -m venv .venv
.venv/Scripts/activate        # macOS·Linux: source .venv/bin/activate
pip install -r requirements.txt
```

키를 환경변수로 넣는다 (PowerShell 예: `$env:OPENROUTER_API_KEY = "sk-or-..."`). 키를 코드나 파일에 적지 않는다.

```bash
python app.py                 # http://127.0.0.1:8000
python search_core.py "민원 상담 챗봇을 도입한 기관"   # 화면 없이 검색만 확인
```

## Vercel 배포

1. GitHub 계정으로 Vercel에 가입한다
2. 이 폴더를 GitHub 저장소로 올린다 (`data/` 색인 파일 포함, 키 파일 제외)
3. Vercel → Add New → Project → 저장소 Import. Application Preset은 Flask
4. Environment Variables에 `OPENROUTER_API_KEY` 입력 → Deploy
5. 받은 주소를 휴대폰 등 다른 기기에서 열어 검색이 되는지 확인한다

Vercel은 `app.py`의 Flask 인스턴스 `app`을 찾아 함수 하나로 실행하고, `public/` 파일은 CDN에서 직접 내보낸다.

## 환경변수

| 이름 | 용도 |
| --- | --- |
| `OPENROUTER_API_KEY` | 질의 문장 임베딩. OpenRouter에서 키 사용 한도를 걸어 둔다 |
| `DATA_GO_KR_SERVICE_KEY` | 공고 수집(`fetch_notices.py`)에만 쓴다. 배포 서버에는 필요 없다 |

## 비교 분석 리포트 메일 받기 (운영사 배포본 전용, kds-lead 브랜치)

결과 카드에서 "비교 담기"로 사업을 고르면, 담당자명·소속·이메일·필요사항을 받아 비교표와 AI 요약을 메일로 보낸다. 같은 내용과 문의자 정보는 운영사 메일로도 간다. 이용자 입력은 서버에 저장하지 않는다.

| 환경변수 | 용도 |
| --- | --- |
| `LEAD_FORM_ENABLED` | `1`이면 켠다. 없으면 화면에 나타나지 않고 `/api/report`는 404 |
| `OPERATOR_NAME` | 화면 꼬리말·개인정보 고지·메일 발신자에 표시할 운영사 이름 |
| `LEAD_TO` | 문의를 받을 운영사 메일 주소 |
| `SMTP_USER`, `SMTP_APP_PASSWORD` | 발송 계정과 비밀번호. Gmail은 앱 비밀번호(16자리), 하이웍스는 메일 계정 비밀번호 |
| `SMTP_HOST`, `SMTP_PORT` | 발송 서버. 기본 `smtp.gmail.com`·`465`. 하이웍스는 `smtps.hiworks.com`·`465`(SSL) |
| `REPORT_MODEL` | AI 요약 모델. 기본 `anthropic/claude-haiku-5.5` |
| `MAIL_DRY_RUN` | `1`이면 메일을 보내지 않고 `cache/outbox/`에 `.eml`로 남긴다(로컬 시험) |

Gmail 앱 비밀번호: 구글 계정 관리 → 보안 → 2단계 인증 켜기 → 검색창에 "앱 비밀번호" → 이름 입력 → 생성(7강 #63).

하이웍스: 웹메일 환경설정의 POP3/SMTP 설정을 "사용 함"으로 바꾼다(계정을 만들면 "사용 안함"). 발송 서버 `smtps.hiworks.com` 465 SSL. 2025년 2월부터 TLS 1.0·1.1은 지원하지 않는다(하이웍스 공지).

## 파일

| 파일 | 내용 |
| --- | --- |
| `app.py` | Flask 서버. `/`(화면), `POST /api/search` 본문 `{"q": "질의", "offset": 0}`(검색, 10건씩 최대 100위) |
| `search_core.py` | 질의 임베딩과 유사도 검색 |
| `report.py` | 비교 분석 리포트 생성·AI 요약·메일 발송 (운영사 배포본 전용) |
| `fetch_notices.py` | 실제 입찰공고 수집과 발주계획 연결 |
| `public/index.html` | 검색 화면 |
| `data/vectors.f16`, `data/docs.json`, `data/index.meta.json` | 색인 (공개 정보만, 담당자 이름·연락처 없음) |
| `build_index.py` | 과제 1 임베딩에서 색인을 다시 만든다. 상위 폴더 `../data`가 있어야 한다 |

색인 다시 만들기: `python build_index.py --source all --dim 1024`

실제 공고 다시 받기: `python fetch_notices.py collect --from 2023-10 --to 2026-10` 뒤 `python fetch_notices.py link` (결과 `data/notices.json`, 수집 원본은 `cache/`로 저장소에 올리지 않음)

## 자주 나는 문제

- "OPENROUTER_API_KEY 환경변수가 없습니다": 환경변수를 넣지 않았다. Vercel에서는 넣은 뒤 다시 배포해야 반영된다
- 검색이 오래 걸린다: 임베딩 API가 가끔 늦다. 화면은 경과 초를 보이고 5초가 넘으면 "응답을 기다리는 중"으로 바꾼다. 서버는 15초씩 최대 2번 기다리고, 화면은 35초가 지나면 멈추고 "다시 시도" 버튼을 띄운다
- 오류 문구가 뜬다: 서버가 원인별로 알려 준다. 시간 초과(504), AI 서비스 사용량 한도(503, OpenRouter 키 한도 확인), 연결 오류(502), 키 설정 문제(500)
- 결과가 이상하다: 사업명만으로 찾기 때문에 이름이 짧거나 일반적인 사업은 잘 걸리지 않는다
- 엉뚱한 질의에도 결과가 나온다: 임베딩 검색은 항상 가장 가까운 것을 돌려준다. 1위 유사도가 0.70 미만이면 화면에 "딱 맞는 사업이 없을 수 있다"를 띄운다
- 건수가 질의마다 크게 다르다: 화면의 건수는 "유사도 70% 이상인 사업 수"다. 일반적인 질의(예: "AI 도입 전략 컨설팅")는 수백 건, 구체적인 질의는 몇 건이 잡힌다. 순위는 더 보기로 100위까지 볼 수 있다
- 비슷한 사업이 한 카드로 묶인다: 같은 기관의 두 사업이 유사도 0.93 이상이면 정정 공고나 해마다 갱신하는 같은 용역으로 보고 "같은 기관의 비슷한 사업"으로 접어 둔다

## 한계

- 발주계획은 사전 계획이라 실제 입찰공고·계약과 1:1이 아니다
- 사업 개요 필드가 비어 있어 사업명만 임베딩했다
- AI 관련 사업 판정은 사업명 규칙이라 오탐이 섞인다. 예: 기관명에 "인공지능"이 들어간 학교의 야구부 전지훈련 용역
- 0.70·0.93 두 기준은 질의 7개와 기관 내 사업 쌍 분포로 정했다. 검증 질의가 적어 경계 근처(예: "CCTV 영상으로 위험 상황을 감지" 1위 0.728)에서는 틀릴 수 있다
- 결과는 정보 제공용이다. 조달·기술 자문이 아니다

## 이것을 해도 되는가 (7강 #84·#86)

| 애매한 점 | 판단 | 극복 수단 | 남은 위험 |
| --- | --- | --- | --- |
| 남의 자료를 공개 웹앱에 올려도 되나 | 조달청 나라장터 발주계획은 공공데이터포털에 공개된 데이터다 | 공개 항목(사업명·기관·금액·연월·원문 링크)만 싣고 출처를 화면에 밝혔다 | 수집은 키 없이 쓰는 공용 프록시(다른 운영자의 키)를 거쳤다. 개인 서비스키를 받으면 직접 받은 데이터로 바꾼다 |
| 개인정보가 들어 있나 | 발주계획과 입찰공고 원본에 담당자 이름·전화번호·이메일이 있다 | 수집 단계에서 버렸다(공고는 쓸 항목만 골라 저장). 색인·공고 파일에서 0건임을 확인했다 | 사업명 안에 개인을 알아볼 수 있는 말이 섞일 가능성은 낮지만 0은 아니다 |
| 업체 정보가 드러나나 | 수의계약 공고 첨부에 업체가 낸 확인서·각서(업체명 포함)가 있다 | 공고문·제안요청서·과업내용서 같은 핵심 서류만 링크하고 업체 서류로 보이는 파일은 뺐다 | 파일명 규칙으로 거르므로 이름에 업체명이 없는 업체 서류는 남을 수 있다 |
| 이용자가 입력한 문장은 어떻게 되나 | 의미 검색을 위해 질의 문장이 외부 AI 서비스(OpenRouter)로 전송된다 | 질의를 저장하지 않는다(로그 DB 없음). 질의가 주소에 남지 않게 POST로 받는다. 화면에 "내부 정보·개인정보는 넣지 않는다"를 고지했다 | Vercel·OpenRouter 쪽 처리 기록은 각 서비스 정책을 따른다. 이용자가 고지를 무시하고 내부 정보를 넣을 수 있다 |
| 누구나 쓰는 공개 URL이어도 되나 | 공개 데이터만 싣고 있어 접근 통제는 붙이지 않았다 | 질의 200자 제한, OpenRouter 키 사용 한도 | 호출 횟수 제한이 없다. 누군가 반복 호출로 한도를 다 쓰면 검색이 멈춘다(비용은 한도 안에서 끝난다) |
| AI 결과를 그대로 써도 되나 | 생성형 답변이 아니라 기존 사업 목록을 의미가 가까운 순으로 보여 준다 | 유사도 표시, 나라장터 원문 링크, 낮은 유사도 안내, 정보 제공용·사전 계획 고지 | 이용자가 "유사도 높음"을 "우리 기관에 맞는 사업"으로 받아들일 수 있다 |
| 조달·기술 자문처럼 보이나 | 추천·평가를 하지 않고 과거 사례를 찾아 줄 뿐이다 | "정보 제공용" 고지를 화면에 고정했다 | RAG 답변을 붙이면 자문처럼 보일 위험이 커진다. 붙일 때 근거 번호 인용과 고지를 강제해야 한다 |

결정과 이유는 DECISIONS.md, 계획은 PLAN.md에 있다.
